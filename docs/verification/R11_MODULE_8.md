## 3. Что проверяет обучение

- Разделение emissions-related OBD и расширенной OEM-диагностики;
  интерфейс/адаптер/ПО/протокол имеют разные ограничения покрытия.
- DLC: лицевой вид автомобильной розетки Type A, широкий край сверху,
  номера 1…8/9…16; питание 16, chassis/signal ground 4/5, CAN 6/14 только
  для соответствующей реализации. Нельзя угадывать остальные контакты.
- Pending/confirmed/permanent, физическая самопроверка MIL и diagnostic
  MIL command, readiness и unsupported — разные сведения.
- DTC P0300/P0171/P0102/P0562/U0100 не определяет деталь для замены.
  Современные полные платные стандарты не объявлены прочитанными.
- FF/LD синтетические и согласованы с режимом/поддержкой полей.
  Есть расчётные/подставленные данные и несинхронный опрос.
- В новом сравнении напряжений U_ECU=11,30−0,10=11,20 V, а падение
  B+→P_ECU=14,20−11,30=2,90 V. Это локализует пути для проверки,
  не приговаривает ECU/генератор и не определяет точный контакт.
- В P0102 дополнительные OFF/изоляция W нужны для обоснованного вывода;
  S/E без этого оставляют альтернативы. Подстановка MAF 3,20 g/s —
  условие модели, не норма или универсальная стратегия OEM.

Итог: ровно 15 вопросов, порог 80%=12/15. Widget journey проходит 11/15
fail → retry снимает ответ → 12/15 при всех отвеченных → одна запись
только после «Завершить проверку». Domain test отдельно запрещает
завершение при 12 правильных и неотвеченном последнем вопросе.

измерение/PID и не скрывает будущие блоки. Графики статические без zoom,
курсора, записи и ветвления; история попыток не сохраняется. Это учебный
анализ предоставленных данных, не виртуальный OBD-сканер.
