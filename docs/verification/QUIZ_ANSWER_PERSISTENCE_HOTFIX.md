## Первопричина и воспроизведение

Итоговый тест — обычный `Lesson` с `completion.type == quiz`, отдельного quiz LessonBlock нет.
`LessonScreen` строил `ListView(children: ...)`. Этот конструктор также использует ленивый
жизненный цикл элементов: State карточки вне viewport/cache уничтожался.
`QuestionBlock.selectedAnswer` и `checked` жили только внутри карточки; `taskResults`
экрана содержал лишь bool после индивидуальной проверки. Черновик туда не попадал.
Стабильный внутренний ValueKey не сохраняет State после удаления элемента.
Соседние ответы не очищались обработчиками setState; причина — уничтожение локального State.

До изменения production-кода два widget-теста воспроизвели дефект на экране 360×640:
реальный `stage_0/lesson_05.json` и обычный урок с шестью вопросами.
Выбор первого ответа, прокрутка к последнему, выбор там, возврат: Expected 0, Actual null.
Оба теста были красными. После исправления те же сценарии проходят.

## Минимальное исправление и UX

- `LessonBlockRenderer` сохраняет State посещённых оцениваемых карточек через
  AutomaticKeepAliveClientMixin. Неоцениваемые иллюстрации/текст остаются ленивыми.
  Typed dispatch остаётся в renderer.
- `LessonScreen` владеет map контроллеров текущей quiz-попытки, статусом отправки и retry.
  `QuizTaskController` хранит выбор/числовой черновик и связывает готовность с существующей
  функцией проверки карточки. Симуляторы сохраняют своё State через renderer; их расчёты не копируются.
- В итоговом тесте одна кнопка «Проверить ответы» в конце; индивидуальные проверки скрыты,
  включая Enter в числовом поле. Пока есть незаполненные задания, кнопка недоступна,
  показано «Осталось без ответа: N». До отправки ответы можно менять.
- Готовность: Q — выбран вариант; C — конечное число (точка/запятая);
  M — включён режим и выбраны оба щупа; VD — выбраны две точки;
  I — включён режим, выбрано подключение, исправен предохранитель;
  O — пользователь изменил настройку/выполнил действие. Готовность не означает правильность.
- Общая проверка вызывает исходные evaluator callbacks всех заданий, затем показывает результат.
  AbsorbPointer + ExcludeFocus блокируют изменение всей попытки мышью/касанием/клавиатурой.
  Только общая «Попробовать ещё раз» создаёт новые карточки/контроллеры и очищает результат.
- Обычный question сохраняет индивидуальную проверку и retry, дополнительно перестаёт
  терять черновик при прокрутке. Проверка/повтор соседнего задания его не очищает.
- Для узкого экрана/увеличенного текста исправлена компоновка результата, разъёмов
  и заголовка провода; дисплеи измерительных quiz-карточек могут расти по высоте.

Scoring не изменён: тот же `evaluateLessonAttempt`, округление, пороги из metadata,
все обязательные задания, существующие математические и электрические правила.
Добавлено только требование общей отправки перед completion quiz.
PASS сам по себе ничего не сохраняет: остаётся явная «Завершить проверку».
Retry/выход без завершения не записывают прогресс и не стирают completed IDs.
Новый вход создаёт новую попытку без ложного PASS. SharedPreferences schema неизменна.
