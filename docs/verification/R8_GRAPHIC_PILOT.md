Пилотные JSON загружаются через существующий `CourseService` и используют только

курса — четыре модуля / 32 урока. Старые JSON и тесты не менялись.

## Схемы и задания на чтение

| Урок / схема | Что изображено | Пример задания и правильный вывод |
| --- | --- | --- |
| 2 / 2A `symbols_lamp` | Батарея, F1, S1, H1 и полный обратный провод | S1 замкнули: выбрать B1+ → F1 → S1 → H1 → B1−; перегоревший F1 прерывает этот путь |
| 2 / 2B `symbols_junction` | Узел с точкой и отдельное пересечение с мостиком | Из E продолжение ведёт к F; G/H не соединены с E/F. В I A связан с B/C/D |
| 4 / 4A `relay_off` | Невозбуждённый K1, NO/NC, отдельная катушка с D1 | Какая лампа получает питание? H2 через F1–30–87a, при исправных остальных элементах |
| 4 / 4B `relay_on` | Возбуждённый K1 и управляющий путь | Путь H1: F1–30–87; питание катушки 86+/85− по стороне катода D1. После отказа F2 и затухания тока реле возвращается к 30–87a |
| 5 / 5A `connector_page_1` | B1/F2, X1:3/4, два разных продолжения | После X1:3 искать A на листе 2 B4, а не любой красный провод или продолжение B |
| 5 / 5B `connector_page_2` | X2:7/8, H2, взаимные ссылки | От A через X2:7–H2–X2:8 вернуться к B; обрыв X1:4 на первом листе прерывает обратный путь |
| 5 / 5C `connector_views` | Один учебный корпус X1, два противоположных вида | Контакт 3 со стороны проводов вверху слева при защёлке сверху; номер контакта не меняется |

Правильные/неправильные маршруты объясняются в feedback. Легенда и описание
соединений помогают читать рисунок, но вопросы требуют применить состояние,
смену вида или переход страницы. На отдельных экранах quiz общая модель не
проверяет нарисованный путь: ответ выбирается из вариантов.

Техническое ревью выполнено по геометрии и заданным связям: длинные положительные
и короткие отрицательные штрихи батареи, отсутствие скрытых перемычек, NC/NO
для двух состояний, механический пунктир, диод K→86/A→85, раздельные защиты,
номера X1/X2 и парные ссылки. Номерные виды относятся к авторскому корпусу,
а не к любому автомобилю. Формальная сертификация соответствия IEC не заявлена;
использованы распространённые символы и явная локальная легенда соединений.

## Ограничения image-блока

1. Нет zoom/pan, выбора узла или проверки траектории. Для этой практики ответы
   даны обычным `question` и не проверяют последовательность касаний рисунка.
2. Состояния статические: два image для OFF/ON. Нельзя взаимодействовать с реле,
   выключателем или измерять произвольные точки. PNG не является simulator.
3. Надписи внутри bitmap не реагируют на увеличение системного шрифта. Поэтому
   они изначально крупные; сложную схему надо разбивать на фрагменты, а не
   уменьшать целую страницу. Полную OEM-страницу этот подход не заменяет.
4. Белый фон SVG/PNG сохраняется в тёмной теме. Контраст внутри схемы стабильный,
   но яркость карточки отличается от окружающего UI; это видно в preview 4B.
5. `BoxFit.cover` при текущих unconstrained image heights сохранил полную схему:
   тесты подтверждают aspect ratio. Если в будущем появятся фиксированные размеры
   контейнера, обрезку нужно проверять снова.
6. Есть только asset и caption, нет отдельного semantic description пространственной
   структуры. Рядом добавлен обычный text, но полноценный accessibility/TalkBack
   audit не проводился. Изображение само не объясняет свою структуру screen reader.
7. Схема и вопрос могут оказаться на разных участках длинного ListView, требуется
   прокрутка назад. Существующий renderer не закрепляет рисунок возле вопроса.

Новые tests проверяют direct course loading и сохранение общего количества 32,
связь каждого image с практическим question, metadata/answers/explanations,
completion ordinary lesson, bundled PNG размеры, геометрию renderer на двух
ширинах/темах, wrong → retry → correct callbacks на реальном вопросе реле.
Они не доказывают электрическую правильность графики автоматически: она
проверена отдельно при ревью SVG и preview.

При подготовке capture два запуска были остановлены из-за ожидания декодирования
в тестовом async-контексте. Исправлен только test harness: очистка rootBundle
cache между тестами и начало image decoding в real async до mount. Следующий
запуск выявил отсутствие `pump` между выбором ответа и нажатием check; добавлен
test pump. После исправлений targeted и полный suite прошли. Production код
для устранения этих тестовых проблем не менялся.

Экспорт первоначально использовал width/height параметры resvg-py 0.2.0, которые
масштабировали рисунок без расширения canvas. Исправлено в tooling: root viewport
×3 с прежним viewBox; размеры и отсутствие обрезки проверены повторно. Новый
decode-test защищает от ошибочного размера PNG. Gradle/JDK при debug build
сообщил предупреждение restricted native access; сборка завершилась успешно,
настройки Gradle/JDK не менялись.

**Рекомендация: на этой основе можно реализовать остальные семь уроков** для
ограниченной цели базового чтения схем. Подтверждены техническая совместимость,
достаточный размер надписей и возможность связывать изображения с практикой;
эффективность для реальных учащихся ещё нуждается в оценке владельцем/новичком.

Для продолжения использовать: небольшие самостоятельные фрагменты, легенду
и состояния, обратный путь, крупные ID; для запуска/зарядки отдельно силовую
и управляющую части; для quiz новые компоновки, а не повтор готовых ответов.
Реле разумно делить на два более коротких фрагмента, если удобство вертикальной
прокрутки не устроит владельца. Не добавлять solver или новые block types.
Если нужна проверка нарисованного маршрута, zoom больших страниц или переход
по клику между листами, сначала вернуться к отдельному согласованию B.

**Остановка:** ожидается подтверждение графического пилота. Остальные уроки
не продолжаются по прямому требованию владельца; полный R8 и R6 не закрыты.
