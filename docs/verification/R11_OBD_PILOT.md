## 2. Технические определения и происхождение

| Материал | Проверенный источник | Граница применимости |
| --- | --- | --- |
| P0102 — низкий вход цепи MAF; P0171 — бедная смесь bank 1; P0300 — случайные/множественные пропуски | [Ford 1999 PCED, DTC Descriptions](https://www.fordservicecontent.dealerconnection.com/pubs/content/~WVX2/~MUS~LEN/14/VX24002.HTM), соответствующие строки | Смысловые переводы OEM-описаний. | P0562 — низкое напряжение системы | [SAE J2012 APR2002](https://law.resource.org/pub/us/cfr/ibr/005/sae.j2012.2002.pdf), доступный индексированный фрагмент B6 | Старая редакция; не заявление о чтении полного современного J2012-DA |
| U0100 — потеря связи с ECM, сокращённое OEM-описание | [GM 18-NA-270, Feb 2019](https://static.nhtsa.gov/odi/tsbs/2019/MC-10156897-9999.pdf), p. 2 | Документ изготовителя в архиве NHTSA; пример повреждения жгута не становится универсальным диагнозом |
| Service 01 PID 04/05/06/07/0B/0C/0D/0F/10/11/42 | [CSS Electronics, техническая таблица Service 01](https://www.csselectronics.com/pages/obd2-pid-table-on-board-diagnostics-j1979), соответствующие строки | Документация производителя логгеров, не сам нормативный текст; min/max кодирования не нормы исправности |
| RPM=(256A+B)/4 | [Elm Electronics ELM327DSK](https://www.elmelectronics.com/wp-content/uploads/2017/01/ELM327DS.pdf), pp. 32–33 | Пример изготовителя интерфейсной микросхемы; не обещание работы любого клона |
| PID 42 — напряжение на модуле, не прямо на АКБ | [SAE J1979 APR2002](https://law.resource.org/pub/us/cfr/ibr/005/sae.j1979.2002.pdf), доступный фрагмент B31, также техническая таблица CSS | Проверен доступный фрагмент старой редакции; не весь стандарт |

Проверка по источникам выполнена 2026-10-16. Полные современные платные
SAE/ISO **не прочитаны**. Русские определения — авторский перевод/пересказ;
графика и учебные вопросы авторские, фирменные изображения не копировались.

Четыре категории строго разделены:

1. Определения DTC/PID — подтверждённые источниками значения с указанной
   редакцией/границей; не спецификация конкретного синтетического двигателя.
2. FF/LD и измерения K — синтетические учебные наблюдения, не автомобильный лог.
3. Аналоговый MAF, допустимые питания/сигнал, слабая pull-down и аварийный
   PID 10 — **допущения модели**, не требования SAE и не стратегия Ford.
4. Причины до измерений — диагностические гипотезы. После изоляции W
   локализуется путь/оконцевания, а не единственная неисправность автомобиля.

## 3. Таблица Freeze Frame

Три разных автомобиля/события, все бензиновые 1,6 L, работают на ХХ,
стоянка. Все числа синтетические. Интерфейс карты предоставляет все
указанные поля; обязательность полного такого generic Mode 02 набора не
заявляется. Время — сохранённое событие до текущего чтения, clock неизвестен.

| Поле | FF-A / P0102 | FF-B / P0171 | FF-C / P0562 |
| --- | --- | --- | --- |
| ECT | 88 °C | 90 °C | 90 °C |
| RPM / скорость | 800 / 0 km/h | 780 / 0 km/h | 750 / 0 km/h |
| Расчётная нагрузка | 22% | 24% | 35% |
| Напряжение ECU | 14,180 V | 14,200 V | 10,800 V |
| MAP absolute | 36 kPa | 42 kPa | 40 kPa |
| MAF | N/A | 2,80 g/s | N/A |
| STFT / LTFT B1 | N/A | +18,8 / +12,5% | N/A |

## 4. Live Data и графики

LD-A/B — один автомобиль FF-B, closed loop, стоянка, воздух 20 °C;
режим устойчив минимум 10 s перед окном. A — ХХ, B — повышенные обороты
без дорожной нагрузки. Переход представлен готовыми данными, не домашним
экспериментом. Все перечисленные PID поддержаны **выбранным** интерфейсом.

| PID / единица | LD-A, приём 0…2 s | LD-B, приём 30…32 s |
| --- | ---: | ---: |
| 05 ECT, °C | 90 | 91 |
| 0F IAT, °C | 25 | 26 |
| 0C, rpm | 800 | 2500 |
| 0D, km/h | 0 | 0 |
| 04 load, % | 24 | 18 |
| 0B MAP absolute, kPa | 42 | 32 |
| 10 MAF, g/s | 2,80 | 8,20 |
| 11 дроссель, % | 12,5 | 18,0 |
| 42 ECU, V | 14,200 | 14,180 |
| 06 STFT B1, % | +18,8 | +3,1 |
| 07 LTFT B1, % | +12,5 | +12,5 |

Значения отображения округлены. Меньшая STFT усиливает гипотезу
неучтённого воздуха на ХХ, но требует проверки впуска/топливоподачи/
измерений. STFT+LTFT не объявлена точной универсальной суммой подачи.
Меньшая load при больших RPM допустима для заданного режима без нагрузки.

`live_graphs`: две отдельные оси RPM/STFT, точки сводок окон условно
в центрах t=1/31 s. Нет линии между окнами и выдуманного непрерывного лога.
Координаты реальных SVG проверены независимым обратным преобразованием:
x=62+t×232/32; RPM y=260−rpm×140/3000; STFT y=540−percent×140/25.
Это визуальное сравнение двух сводок, не времена ECU samples.

LD-C — тот же автомобиль FF-A, стоянка/устойчивый ХХ ≥10 s, воздух 20 °C.
Последовательный приём: ECT 90 °C в 0,00 s; 800 rpm в 0,15;
0 km/h в 0,30; load 22% в 0,45; MAP 36 kPa в 0,60; IAT 25 °C в 0,75;
дроссель 12,5% в 0,90; ECU 14,180 V в 1,05; MAF 3,20 g/s в 1,20.
Последнее — аварийная расчётная подстановка по отдельному допущению модели,
не доказательство исправного MAF и не вывод из экрана. STFT/LTFT N/A.
Тексты LD-C в уроках 7/9 и FF-A в уроках 6/9 проверяются на совпадение.

## 5. Техническое ревью P0102

K1: код/статус/симптомы плюс FF-A и LD-C дают несколько гипотез.
K2: функциональная схема P/G/S/E, путь W и оконцевания X1/X2; слабая
pull-down на входе и аварийный PID явно обозначены как модель.
Вход не объявляется низким при любом возможном устройстве MAF.

| Этап / red-black | Состояние | Наблюдение / допустимый вывод |
| --- | --- | --- |
| K3, B+/B− | t=20…24 s; 90 °C; 800 rpm; 22%; стоянка; нагрузка неизменна | 14,20 V на АКБ в данный момент |
| K3, P/B− | Датчик подключён, рабочая нагрузка | 14,15 V |
| K3, G/B− | Та же нагрузка | +0,03 V; не проверка любой нагрузки |
| K3, S/G | Повторяемое внешнее V DC | 1,40 V — ожидаемый выход по условию |
| K3, E/G | То же устойчивое состояние | 0,10 V — низко на конце входа; нужно разделить путь и влияние ECU |
| K4, W между X1/X2 | t=10 min; OFF; ECT 35 °C; 0 rpm; load N/A; нет напряжения; оба устройства отсоединены; нет параллельных путей | >1 MΩ при норме учебного сегмента ≤1 Ω; прибор/контакт щупов проверены |

Точность DMM ±0,02 V. По модели P–G=14,15−0,03=14,12 V, допустимо
13,5…14,5 V; G–B−≤0,05 V при рабочей нагрузке. Условия выполняются с
указанной точностью. Это заданные критерии упражнения, не нормы OEM.
Ожидаемый S–G=1,40±0,05 V; разность S/E около 1,30 V.

**K3 недостаточно для окончательного диагноза:** устойчивое различие
сигналов направляет на проверку доставки/входа. **K4 независимо обнаруживает
нарушение проводимости изолированного W/оконцеваний.** Совокупность данных
обосновывает локализацию этого участка и согласуется с низким E при
заданной подтяжке. Конкретный контакт или внутренняя деталь датчика не
определены. Сопутствующая неисправность не исключена.

K5 появляется после представления дополнительных наблюдений и вопроса
локализации. K6 — план, а не выдуманный успешный результат ремонта:
локализовать W, восстановить соединения, повторить рабочие S/E и симптомы,
проверить статусы/мониторы по процедуре. Clear не заменяет ремонт, а stored
не обязан исчезать немедленно. Сопротивление на включённой электронике,
подача питания на E, отключение систем безопасности или работа в движении
не предлагаются. Ревью выполнил агент по actual content/scheme; независимое
экспертное или автомобильное подтверждение не заявляется.

## 6. Визуализации и педагогические ограничения

Девять оригинальных SVG/PNG перечислены в [provenance README](../../assets/images/obd/README.md).
[Галерея](r11_pilot/preview.html) содержит 18 Flutter captures, 360 px,

179 меток SVG минимум 18 px проверены на границы canvas по Arial.
Дополнительно renderer проверен при 320 px; отсутствие overflow не
равнозначно одинаковой удобочитаемости при уменьшении PNG-текста.
Все non-image блоки проверены при 360 px в обеих темах ×1,3.

Контраст обеспечивает белый фон/тёмные метки; ключевые сведения повторены
масштабируемым Flutter-текстом. Пунктир W — проверяемый путь, не рисунок
точного обрыва. Карточки сканера нейтральные, коммерческий UI не копирован.

Это последовательный разбор, а не новый диагностический workflow:

- Следующие блоки доступны прокруткой до ответа; программного раскрытия
  только после «измерения» нет. Ученик получает готовые наблюдения.
- Question принимает один вариант; «несколько гипотез» и «обоснование»
  проверяются выбором полного набора/аргумента, не оценкой свободного текста.
- Ответ не опрашивает PID, не запускает измерение и не меняет электрическую
  модель. `DiagnosticCase`/`DiagnosticChoice` не переиспользованы.
- Per-question retry снимает ответ; сохранение возможно только после всех
  правильных заданий и отдельной кнопки. Истории попыток/графиков нет.
- Hidden pilot требует тестового/direct asset открытия, а не пользовательской
  навигации. Публикация stage_7 и остальные уроки ждут отдельного разрешения.
