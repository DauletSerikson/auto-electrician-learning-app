в `lib/pilots/oscilloscope_pilot_lesson.dart`, а не зарегистрирован в assets.

настройки и захваты живут в текущем экране. Persistence/schema не менялись.

После проверок сохранены два локальных артефакта:

- `build/app/outputs/flutter-apk/app-course-debug.apk` — основной курс;

## Архитектура и совместимость

- `lib/simulation/scope_signal.dart`: sealed ScopeSignal и PeriodicScopeSignal,
  отдельные constant/sine/pulse/missing-pulse модели, typed сценарии/фронты,
  аналитические пересечения и точные переходы. Без Flutter.
- `lib/simulation/oscilloscope_simulation.dart`: immutable ScopeSettings,
  ScopePoint/ScopeCapture, запись, координатные преобразования и проверка
  трёх настроечных упражнений. Список точек захвата неизменяемый.
- `lib/models/oscilloscope_lesson_block.dart` — part библиотеки LessonBlock:
  один новый final subtype OscilloscopeLessonBlock, JSON type `oscilloscope`.
  Это сохраняет sealed-иерархию и не раздувает прежние классы nullable-полями.
- `OscilloscopeBlock` владеет сессионными настройками/выбранным сценарием/ответом.
  `ScopeDisplay`/`ScopePainter` рисуют готовые domain-данные. Новый case добавлен
  в LessonBlockRenderer; диспетчеризация не переносилась в LessonScreen.
- В `isScoredLessonBlock` добавлено распознавание нового subtype. Формула
  LessonAttempt, требования completion и bool callback API **не изменены**.
  Проверка настройки даёт один bool, смена проверенных настроек/сигнала,
  новый Single capture или reset снимают ответ через onRetry.
- LessonScreen, ProgressService, SharedPreferences и прежние симуляторы
  не менялись; dependencies не добавлялись.

JSON требует `title`, `question`, `scenario`, `exercise`, `initialSettings`.
В настройках обязательны `voltsPerDiv`, `millisecondsPerDiv`, `centerVoltage`,
`triggerLevel`, `edge`, `mode`. Enum имена совпадают с Dart names. Неизвестные
имена, пропуски, неверные типы, NaN/Infinity и неподдерживаемые настройки дают
FormatException. Недостижимый уровень 6 V валиден как учебное условие.
Целевой сценарий настроечных упражнений должен быть периодическим; constant
и missingPulse доступны для исследования через выбор сигнала, но не служат
целями этих трёх упражнений. JSON не является произвольным редактором генератора.

## Физические модели

Все сигналы **синтетические**. Измеряемая величина — напряжение в V относительно
условной N = 0 V. Время модели — секунды, UI — ms. Связь по постоянному току,
идеальный высокоомный вход; нет автомобиля, реального прибора и измерения тока.

| Сценарий | Формула и применимые параметры |
| --- | --- |
| constant | u=2,5 V. Размах 0; период, частота и duty неприменимы |
| sine | u=4 sin(2π·100t) V. A=4 V, U0=0 V, диапазон −4…4 V, Vpp=8 V, T=10 ms, f=100 Hz |
| square | u=5 V в первые 50% каждого периода, иначе 0 V. T=10 ms, f=100 Hz, tHigh=5 ms, среднее 2,5 V |
| pwm30 / ШИМ A | 0/5 V, T=10 ms, f=100 Hz, tHigh=3 ms, DHigh=30%, среднее 1,5 V |
| pwm60 / ШИМ B | 0/5 V, T=10 ms, f=100 Hz, tHigh=6 ms, DHigh=60%, среднее 3 V |
| missingPulse | Несущая pwm30; полностью подавлен один высокий импульс [20,23) ms. Общая запись непериодическая; T/f/D всей записи не приписываются |

Для pulse: u=UH на [kT,kT+DT), иначе UL; f=1/T,
tHigh=DT, Uavg=UL+(UH−UL)D. Длительность события missingPulse задаётся carrier
и missingIndex; это отдельный тип, не наследник PeriodicScopeSignal.
UI явно отделяет параметры несущей от отсутствующего общего периода записи.
Внутри pure Dart конструкторы также валидируют конечные величины, диапазон
напряжения −100…100 V, частоту 1…1000 Hz, A>0, UH>UL, 0<D<1 и missingIndex 1…100.
В UI доступны только перечисленные фиксированные сценарии.

## Запись, масштабирование и триггер

Детерминированная исходная запись: [0,200 ms]. Для гладкой линии шаг 10 µs;
переходы импульсов дополнительно включены с обеих сторон в точное время события.
Поэтому короткий импульс не исчезает только из-за несовпадения с шагом графика.
Сигнал не восстанавливается из пикселей. Это аналитическая учебная модель,
а не эмуляция реального ADC с частотой дискретизации 100 kSa/s.

Экран имеет 10×8 делений. При центре C, масштабе Sv V/div и St s/div:

```text
окно = 10 St
x/W = (t − tStart) / (10 St)
y/H = 1/2 − (u − C) / (8 Sv)
```

Преобразование применяется только к виду, не к физическим параметрам.
Ноль отмечается белой линией, L — пунктир уровня, T — момент запуска;
вне границ линия геометрически обрезается, UI сообщает об обрезании сигнала.
Шкала времени показывает абсолютное положение окна в исходной записи.

Алгоритм запуска:

1. Для синусоиды вычисляются пересечения через asin с нужным знаком производной.
   Касание экстремума и уровень вне диапазона событием не являются.
2. Для ступени rising: before < L и after ≥ L; falling: before > L и after ≤ L.
   Поэтому rise в точности до UH допустим, а rising при L=UL нет;
   falling до UL допустим, а falling при L=UH нет. У constant пересечений нет.
   При t=0 у pulse нет rising: предыдущий низкий уровень не записан.
3. У пропавшего импульса исключаются оба его перехода. Не создаётся ложное
   событие на ожидаемом, но отсутствующем фронте.
4. Из пересечений берётся первое с 20% предыстории и 80% после события внутри
   записи. Границы сравниваются с допуском 10⁻¹² s против double rounding;
   начало окна ограничивается допустимым интервалом, wrap-around отсутствует.
5. Normal без события показывает ожидание и пустую сетку. Auto без события
   показывает окно от t=0 с явной надписью «без синхронизации», без маркера T.
   Если пересечение найдено, Auto действительно синхронизируется.
6. Single очищает прежний захват при смене настроек. По «Захватить» ищется
   событие, после успеха immutable capture остаётся остановленным. Нет события —
   захвата нет. Каждое новое нажатие повторно запускает поиск в той же записи.

Нет непрерывного времени: кнопка Single захватывает фиксированную учебную
запись, а не ожидает внешний сигнал. Настройки не переименовывают старый trace.

## UI, упражнения и оценка

Доступны выбор шести сценариев, V/div 0,5/1/2/5, ms/div 1/2/4/10,
центр −2/0/2,5/5 V, уровень −2/0/2,5/6 V, оба фронта и три режима.
Выбор через раскрывающиеся сенсорные списки; каждый control меняет захват или
отображение. Кнопка захвата видна только в Single. Параметры генератора модели
раскрываются после проверки и прямо названы параметрами, не измерениями экрана.

Пилот содержит шесть оцениваемых заданий по пяти требуемым направлениям:

1. V/div для синусоиды: размах занимает 50–90% высоты, без clipping.
2. ms/div для square: видны 2–5 полных интервалов между одинаковыми rising
   фронтами, без clipping по напряжению. Просто окно шириной 2T ещё может
   содержать лишь один целый интервал из-за положения начала окна.
3. Триггер для ШИМ A: Normal, rising, реальное событие и отсутствие clipping.
4. Два CalculationBlock: T=5 div×2 ms/div=10 ms и f=1/0,010=100 Hz.
5. QuestionBlock: сравнение ШИМ A/B при одинаковом периоде, разное DHigh.

Для трёх настроек проверяется исходный целевой сценарий, чтобы смена сигнала
не позволяла обойти задачу. Ответы на расчёты/сравнение — штатные widgets;
обычный урок требует все шесть правильных ответов и отдельную кнопку завершения.
Интерактивные задания имеют несколько допустимых настроек там, где условия
действительно выполнены. Проверка производится по domain-данным, не по пикселям.

## Ограничения и следующий этап

Нет реального измерения, подключения оборудования, continuous acquisition,
шума/полосы/aliasing ADC, AC coupling, hysteresis, holdoff, аппаратных пределов,
курсоров, двух каналов, CAN/LIN decoder, процедур SRS/HV. Данные не выданы за
реальные осциллограммы автомобиля. Из формы напряжения нельзя подтвердить ток,
механическое движение или исправность массы под нагрузкой.

До полного модуля: решение владельца по пилоту, ревью педагогических критериев,
паспорта остальных сигналов и иллюстраций, согласование API задач и дальнейшее
тестирование на Android/TalkBack. Мелкие canvas-подписи не являются полноценным
доступным табличным представлением всей осциллограммы. Новые уроки, decoder,
persistence или новый общий scoring не внедрять попутно.

`flutter devices --machine` показал Windows, Chrome и Edge, физического Android
или эмулятора нет. Device smoke, реальные сенсорные жесты и TalkBack не проверены;
widget taps и APK build не заменяют эти проверки. R6 Android QA остаётся отдельным.
После R14.2A — STOP; push/merge/tag/GitHub Release не выполняются.
