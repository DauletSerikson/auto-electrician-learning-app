## 2. Образовательные результаты и связь с курсом

Новичок без автомобиля и прибора должен уметь выбирать осциллограф по задаче,
читать напряжение во времени, отличать периодический процесс от разового,
выбирать V/div и ms/div, учитывать ноль и смещение, объяснять запуск по фронту,
измерять размах, амплитуду относительно среднего уровня, период, частоту,
длительность и заполнение. Он должен сравнивать записи при одинаковых условиях,
различать наблюдение, гипотезу и подтверждение, выбирать дополнительную проверку
и отказываться от подключения при неизвестной безопасности.

| Предыдущий модуль | Что используем в модуле 11 |
| --- | --- |
| 1, stage_0: безопасность | КЗ, ограничения SRS/HV, безопасное решение «остановиться» |
| 2, stage_1: электричество | Разность потенциалов, ток, сопротивление; единицы и расчёты |
| 3, stage_2: мультиметр | Опорная точка, режим и вход; ограниченность одного числового показания |
| 4, stage_3: электрооборудование | Питание, масса, нагрузка и падение напряжения |
| 5, stage_4: схемы | Узлы, путь тока, точки подключения каналов |
| 6, stage_5: диагностика | Проверяемая гипотеза, условия измерения, пределы доказательств |
| 7, stage_6: электроника | Датчики, ключи, ШИМ, CAN/LIN — теперь форма во времени |
| 8, stage_7: OBD | DTC/Live Data сопоставляются с записью; код не доказывает отказ детали |
| 9, stage_8: запуск/зарядка | Скорость прокрутки и питание как условия записи |
| 10, stage_9: проводка | Контакт/жгут как альтернативная причина нарушения сигнала |

Каждый урок: теория → подписанный пример → действие/расчёт → объяснение
ошибочного вывода → закрепление. Все обязательные действия выполняются офлайн.

## 4. Что фактически поддерживает архитектура

Изучены `lib/models/lesson_block.dart`, `LessonBlockRenderer`, `LessonScreen`,
`domain/lesson_attempt.dart`, CourseService/ProgressService, widgets и pure Dart
`simulation/`, а также parsing/content, quiz, diagram и storage tests.

| Существующий тип | Применимость и ограничение |
| --- | --- |
| Text / Remember / Warning | Теория, условия, ограничения и безопасность |
| Image | `Image.asset(..., fit: BoxFit.cover)` и подпись. PNG поддерживается; SVG renderer, zoom, курсоров и смены кадра нет |
| Question | Один ответ из текстовых вариантов, проверка и retry; нет изображений внутри вариантов |
| Calculation | Один числовой ответ, абсолютный допуск, точка/запятая; formatter не допускает минус и экспоненту. Знаковые ответы задавать вопросами, а не менять UI попутно |
| Circuit | Специализированные DC-цепи/лампы и переключатель; не временной solver, не оценивается LessonAttempt |
| Multimeter | Демонстрация режимов/подключений; не генератор осциллограмм, не оценивается |
| Measurement | Четыре subtype: АКБ, сопротивление провода, прозвонка, сопротивление; не временные данные |
| VoltageDrop | Проверки падения напряжения в своей DC-модели |
| CurrentMeasurement | Собственная модель включения амперметра/предохранителя |
| DiagnosticCase | Заданная DC-цепь, измерения с immutable record состояния питания; сохранить регрессию |
| DiagnosticChoice | Таблица измерений для фиксированных faultType и выбор диагноза; не произвольный движок кейсов |

Итого 13 JSON-типов, а не 13 конечных Dart-классов: measurement имеет подтипы.
Ни один существующий simulator не предоставляет временную запись, выбор
V/div/ms/div или триггер. Переключение питания в DC-упражнении не является
переключением осциллограмм. Не расширять faultType ради имитации новых кейсов.

`LessonBlockRenderer` диспетчеризирует subtype; `LessonScreen` хранит
`Map<int, bool>`, обрабатывает onAnswered/onRetry и explicit completion.
`evaluateLessonAttempt` считает семь групп оцениваемых блоков; обычный урок
требует всех правильных, quiz — всех отвеченных и порога по округлённому проценту.
При 15 заданиях 12/15 = 80%, 11/15 = 73%, неоднозначности округления нет.
`ProgressService` сериализует read-modify-write и хранит только completed IDs;
ошибки чтения/сохранения имеют retry. Настройки прибора, ответы, баллы и история
не сохраняются. Новая практика должна пользоваться этим контрактом.

## 5. Каталог моделей и электрические условия

Все записи ниже **синтетические учебные**, не сняты с автомобиля. Величина —
напряжение в V, время вычисляется в s, подписи — ms/µs. DC coupling; вход
высокоомный, нагрузкой щупа в числовой модели пренебрегаем, в безопасности
объясняем её наличие. N — заданная опорная точка 0 V, а не доказательство
исправной массы. Для двухпроводного индуктивного датчика используется разность
выводов A–B и подходящий дифференциальный вход, не зажим общей земли на B.
Пределы реального оборудования из учебных уровней не выводятся.

Для каждой будущей записи обязателен паспорт: ID, происхождение, схема/узлы,
состояние питания/нагрузки/скорости, величина, единицы, опора, DC-составляющая,
min/max и определение амплитуды, окно и шаг времени, V/div, время/div, положение
нуля, параметры триггера, T/f/tHigh/D либо «не применимо», допущения, ответ и
допуск. У непериодической записи не придумывать период/заполнение. Все варианты
и искажения наследуют паспорт родителя с явно перечисленными изменениями.

Для S8 среднее каждой линии вычисляется по доле dominant в данном окне,
для S9 — по доле recessive; в подписи конкретной иллюстрации указывать её
значение. S5/S6 сравниваются на общем временном основании с известной фазой.
В S5 при 1200 rpm все интервалы вдвое короче, уровни Hall остаются 0/5 V.
Для индуктивного варианта только учебное приближение: при удвоении скорости
uAB=8 sin(2π·200t); реальная зависимость амплитуды требует данных датчика/зазора.

### Формулы и ограничения

- Синус: u(t)=U0+A sin(2πft+φ); Vpp=2A; A измеряется от U0, не от края экрана.
- Период: T=Δn·timePerDiv; f=1/T. Напряжение: ΔU=Δn·voltsPerDiv.
- PWM: DHigh=tHigh/T; проценты=100D; Uavg=UL+(UH−UL)D для идеальных уровней.
  Слова «амплитуда PWM» заменять явными UL/UH/Vpp, чтобы избежать двусмысленности.
- Для low-side нагрузка включена при низком напряжении ключа; DOn не равно
  DHigh на этой точке. S7: DOn=40%, высокий участок с выбросом занимает 60%.
  При таком выбросе среднее нельзя считать как 12·DHigh.
- High-side сравнительный пример S7H: учебная резистивная нагрузка 12 Ω к N,
  питание 12 V, ключ подаёт плюс 8 ms из 20 ms; uLoad=12q, DHigh=DOn=40%,
  среднее 4,8 V, 0…12 V, окно 40 ms, 4 ms/div, 5 V/div, центр 6 V.
  Выброса нет, поскольку этот пример резистивный; не переносить на катушку.
- Шумовой вариант S2N: uS2+0,1 sin(2π·1000t); источник помех задан математически,
  окно 100 ms, диапазон гарантированно внутри 0,9…4,1 V; указывать, что источник
  реального шума по форме не определён. Zoom-вставка 5 ms показывает помеху.
- Для непериодических данных — интервалы/длительность события; отсутствие
  наблюдаемого импульса не доказывает обрыв, ошибку механики или отказ ECU.
- S8/S9 — эскизы физического уровня без кадрового форматирования/CRC/декодера.
  Нельзя по ним оценивать валидность сообщения. Типичные уровни не являются
  универсальными допусками всех CAN/LIN вариантов.

## 6. Шесть комплексных кейсов

Каждый кейс включает отдельные карточки условий/схемы/записи, гипотезы,
допустимый вывод и следующую проверку. Таблица задаёт все отличия от паспортов.

| Кейс | Условия, модель и настройка | Наблюдение, гипотезы и допустимый вывод | Дополнительная проверка |
| --- | --- | --- | --- |

## 8. Безопасность подключения

Курс учит принимать решение по схеме и паспортам, а не предписывает универсальное
подключение к автомобилю. Все обязательные упражнения виртуальные.

1. До выбора точки выяснить архитектуру входов: single-ended/common-ground,
   индивидуально изолированные или дифференциальные. USB, аккумуляторное питание
   и слово «автомобильный» сами по себе не означают изоляцию.
2. У настольного прибора общий может быть связан с PE. Несколько common-ground
   зажимов электрически соединены; крепление к разным потенциалам создаёт КЗ.
   Учитывать также USB/зарядник/подключённые внешние приборы. PE не отключать.
3. Измерение относительно N/массы разрешено в учебной схеме при явно заданной
   совместимости оборудования. В реальности нужны руководство прибора,
   схема автомобиля и проверка допустимых связей, а не предположение о «нуле».
4. Разность A–B требует подходящего дифференциального/изолированного решения.
   Математическое CH1−CH2 не устраняет опасную связь общих проводов и не
   расширяет пределы каждого входа.
5. Проверять максимальное рабочее и импульсное напряжение, common-mode,
   допустимую разность, категорию применения, полосу, делитель и его настройку.
   Увеличение V/div меняет изображение, не допустимое напряжение входа.
   Щуп ×10/делитель сам по себе не создаёт гальванической изоляции.
6. Индуктивные выбросы могут значительно превышать бортовые 12 V; S7 — только
   заданный пример, не верхний предел. Не подключать обычный вход к первичной/
   вторичной цепи зажигания или форсунке без подходящего оборудования/процедуры.
7. Ёмкость/сопротивление щупа и длинная петля земли могут менять/искажать сигнал.
   Ошибку захвата и подключения исключать перед выводом о неисправности.
8. Не допускать замыкания соседних контактов наконечником; способ доступа к
   разъёму определяется процедурой без повреждения изоляции/контактов.
9. SRS/пиропатроны: произвольные подключения и пробные измерения исключены.
   HV гибридов/EV и сеть питания исключены из практики новичка; нужны обучение,
   допуски и специализированная процедура. Курс не даёт права таких работ.
10. Нет паспорта, схемы, известной опоры или допустимого диапазона — STOP.

Опора на первичные материалы: [Tektronix о floating measurements и защите](https://download.tek.com/document/51W_10640_1.pdf),
[PicoScope 3000 Automotive manual](https://www.picotech.com/download/manuals/ps3000a044-2.pdf),
[Pico о разных common-ground и floating-input конструкциях](https://www.picoauto.com/library/picoscope-automotive-training/training/voltage-drop-techniques-introducing-floating-inputs).
Это примеры конструкций; характеристики выбранного реального комплекта
проверяются по его руководству, а не переносятся с другого прибора.

Для физического уровня использованы [TI CAN PHY Training](https://e2e.ti.com/cfs-file/__key/telligent-evolution-components-attachments/00-138-01-00-00-47-61-86/2011_2D00_09_2D00_06-Texas-Instruments-CAN-PHY-Technical-Training.pdf)
и [NXP TJA1421 LIN transceiver](https://docs.nxp.com/bundle/TJA1421/page/topics/lin_transceiver.html).
Формулы, уровни и диски S1–S9 — авторские учебные допущения; эти источники
не подтверждают универсальный автомобильный эталон или придуманные неисправности.

## 10. Проект ограниченного MVP C (только предложение)

### Объём и состояние

Один канал напряжения, фиксированное DC coupling, идеальные S1 и S3, отдельные
детерминированные сценарии. Выбор сигнала разрешён только в ознакомительном
упражнении; оцениваемое задание фиксирует сценарий. Сетка 10×8. Списки настроек:
V/div 1/2/5; time/div 1/2/4/10 ms; центр −2/0/2,5/5 V; уровень trigger 0/2,5/6 V;
rising/falling; Normal/Auto/Single, кнопки захвата и проверки. Каждый сценарий
задаёт допустимое подмножество. Для MVP не нужны шум, CAN/LIN, выбросы, два канала,
курсоры, аналоговый frontend, реальное время, аудио или continuous animation.

Пример цели: S3 полностью виден, окно содержит 2–5 периодов, Normal rising 2,5 V,
сигнал захвачен. Правильных комбинаций может быть несколько; оценивать условия,
а не совпадение с одной пресетной настройкой. Одна такая задача даёт один bool.
Частоту/заполнение в оцениваемой практике скрывать до проверки; в ознакомлении
показывать их как параметры модели, не выдавать за автоматический анализ записи.

### Математика отображения и триггер

Пусть центр C в V, масштаб Sv V/div, St s/div, размер W×H.
Окно равно 10St; x=W(t−tStart)/(10St),
y=H/2−H(u−C)/(8Sv). Изменение C меняет вид, не источник/амплитуду.
Отмечать положение 0 V, обрезание границ и недостающий захват явно.
Линии за пределами области отсекать геометрически, не подменять реальные min/max.

Детерминированная запись 0…200 ms, модельный шаг 10 µs (100 kSa/s),
исходные функции и точные события известны; экранная полилиния строится по
модели, а не повторно семплируется из пикселей. Край ступени сохранять как
событие, не сглаживать. Реальные aliasing, bandwidth, ADC noise и memory depth
объясняются как исключённые ограничения; учебные 100 kSa/s не характеристика
автомобильного прибора. Не показывать превышающие модельную полосу сигналы.

Запуск ищется в исходных данных до экранного downsampling: rising — переход
с u<L к u≥L, falling — с u>L к u≤L. Для гладкой функции определить пересечение,
для ступени — время события. На границах диапазона без строгого пересечения
запуска нет; правило описано в подсказке. Удержание/hysteresis не моделируются.
Нужны 20% предыстории и 80% после события; брать первое подходящее событие,
для которого полное окно помещается в запись, никаких скрытых wrap-around.

- Normal без пересечения: статус «ожидание запуска», новый кадр отсутствует.
- Auto без пересечения: детерминированное окно с начала записи и заметная
  метка «автозапуск, без синхронизации», не ложный triggered status.
- Single: arm → первый допустимый trigger → immutable capture → остановка.
  Нет trigger — остаётся armed; новый захват только после повторного arm.
- После смены сигнала/настроек сбрасывать старый capture/проверенный ответ,
  чтобы график и scoring не относились к разным состояниям.

### Предлагаемые модели/API и интеграция

Названия ниже проектные, не существующие API. `OscilloscopeLessonBlock` содержит
scenario, initialSettings, разрешённые controls и typed task criterion;
сигналы — sealed `SineSignal`/`PulseSignal`, без набора несвязанных nullable полей.
Валидация: конечные числа, T>0, 0<D<1 для pulse, UH>UL, положительные масштабы,
известные scenario/mode/edge и совместимость задачи/настроек; ошибочный JSON
даёт FormatException, без fallback. Уровень вне диапазона допустим как упражнение.

Pure Dart в `lib/simulation/`: immutable `ScopeSettings`, `ScopeState`,
`ScopeCapture`, `ScopeTaskResult`; операции `setSettings`, `selectSignal`,
`arm`, `capture`, `evaluateTask`, `reset`. Вход — typed scenario/settings/state,
выход — новое состояние, точки/события, статус запуска/обрезания и результат;
без Flutter, таймеров, storage и оценки по пикселям. Отдельно определить равенство
и проверки диапазонов; не вводить framework ради управления несколькими полями.

Widget в `lib/widgets/lesson_blocks/` владеет сессионным состоянием, painter
только рисует. Renderer получает новый type-based case; LessonAttempt — явное
включение нового оцениваемого типа. onAnswered(bool) вызывается по «Проверить»,
onRetry снимает ответ при retry/изменении настроек после проверки.
LessonScreen и ProgressService сохраняют свои роли; storage schema прежняя.
Старые parsing, simulator behaviour и immutable DiagnosticMeasurementRecord
не меняются. Разделить изменения на модель/домен → widget → пилот → остальной
контент; не переписывать существующие симуляторы.

### Оценка трудоёмкости

Инженерная оценка для одного разработчика, без обещания срока: модель/trigger
и unit tests 2–3 дня; renderer/controls и widget tests 2–3; scoring/retry,
пилот, адаптивность и ревью 2–4. Итого **6–10 рабочих дней только MVP C**.
Полный авторинг десяти уроков/иллюстраций и независимая техническая проверка
оцениваются отдельно. Если потребуются continuous acquisition, два канала,
перетаскиваемые курсоры или декодер — переоценка и отдельное согласование.
