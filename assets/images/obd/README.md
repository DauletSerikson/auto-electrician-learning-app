# Авторские материалы OBD-пилота R11.2A

Созданы Codex по заданию владельца 2026-10-16. SVG-примитивы, компоновки,
карточки и графики авторские; сторонние иллюстрации, OEM artwork, логотипы
и фирменные UI не копировались. Распространение — MIT проекта. Шрифт Arial
использован локально при экспорте, его файл не распространяется.

| SVG source / PNG | Содержание | PNG, px |
| --- | --- | --- |
| `dtc_structure` | Пятисимвольный код и области P/B/C/U | 960×1620 |
| `freeze_a` | Синтетический FF-A / P0102 | 960×2037 |
| `freeze_b` | Синтетический FF-B / P0171 | 960×2037 |
| `freeze_c` | Синтетический FF-C / P0562 | 960×2037 |
| `live_a` | LD-A, ХХ, окно приёма 0…2 s | 960×2538 |
| `live_b` | LD-B, повышенные обороты без дорожной нагрузки, 30…32 s | 960×2538 |
| `live_graphs` | Два графика сводок RPM/STFT; без интерполяции между окнами | 960×2136 |
| `maf_circuit` | Функциональная модель P/G/S/E/W; не универсальная распиновка | 960×2430 |
| `diagnostic_path` | Схема рассуждения, не программное ветвление | 960×1794 |

Все числа — синтетические условия [утверждённого плана](../../../docs/roadmap/R11_MODULE_8_PLAN.md).
Не реальные записи, не OEM-допуски. Источники определений и техническое
ревью — в [отчёте пилота](../../../docs/verification/R11_OBD_PILOT.md).
Данные и ограничения повторены обычным Flutter-текстом рядом с image.

SVG находятся в `source/`, не входят в bundle. PNG экспортированы ×3 через
`tools/render_obd_assets.py`, resvg-py 0.2.0 из существующего R10 tooling.
При воспроизведении нужен доступный resvg-py в Python environment;
Flutter dependency не добавлена. Исходная ширина 320, подписи минимум 18;
при viewport 360 и padding 20 отображение имеет ширину 320 logical px.
Непрозрачный белый фон и тёмные подписи сохраняют контраст в двух темах.
TextScaler меняет Flutter-текст, но не PNG-подписи.

Пунктир W обозначает проверяемый сегмент, а не заранее найденный обрыв.
P/G и питание ECU показаны функционально: падения на проводке возможны,
идеальное равенство потенциалов не подразумевается. Входная pull-down
обозначена функционально, не номиналом резистора. Схема не задаёт численное
напряжение E при любом обрыве: 0,10 V — отдельное наблюдение.

Точки графика стоят в центрах окон 1/31 s только для сравнения сводок;
это не точные времена измерения внутри ECU и не дополнительные samples.
Между окнами нет линии и нет данных. Каждый график имеет свою ось/единицу.

## Дополнение полного модуля R11.2B–R11.4

Пять новых композиций созданы 2026-10-16 тем же авторским способом и под
теми же условиями MIT. Девять SVG/PNG пилота сохранены без изменений.
Новый renderer: `tools/render_obd_module_assets.py` использует существующие
SVG helpers и resvg-py, экспортирует только следующие новые файлы:

| SVG source / PNG | Назначение | PNG, px |
| --- | --- | --- |
| `diagnostic_chain` | Система → ECU → интерфейс → сканер → проверка | 960×1584 |
| `dlc_front` | Лицевая розетка Type A, нумерация 1…16 и выделение питания/масс/CAN | 960×2025 |
| `scanner_scope` | Разные уровни покрытия, чтение и вмешательство | 960×1374 |
| `dtc_status` | Различие pending/confirmed/permanent, MIL и readiness | 960×1584 |
| `compare_voltage` | Три потенциала относительно B−, отдельная синтетическая карта C | 960×2094 |

Итого 14 пар, включая два графика RPM/STFT пилота и новую диаграмму трёх
потенциалов. У новой диаграммы общая ось 0…15 V; G=0,10 V не увеличен
искусственно. U_ECU=P_ECU−G_ECU. Все числа/условия повторены в уроке 8.
Это последовательные DMM/PID наблюдения устойчивого режима, не общий sample.

Для DLC вид со стороны прибора в лицевую часть автомобильной розетки,
широкая сторона сверху: верх 1…8, низ 9…16 слева направо. Ориентация и
назначения подтверждены документацией Elm Electronics, не копированием
рисунка. Форма схематическая, не размерный чертёж J1962. Оставшиеся контакты
не названы свободными/безопасными для подключения. Цвет дополнен номером
и текстом; нет обещания CAN на каждом авто.

Все пять новых композиций проверяются на 360 px в обеих темах с текстом
×1,3. [Галерея](../../../docs/verification/r11_module8/preview.html) и
[техническое ревью](../../../docs/verification/R11_MODULE_8_TECHNICAL_REVIEW.md).
